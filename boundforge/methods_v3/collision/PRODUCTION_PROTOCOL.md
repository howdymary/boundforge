# Separate bounded C3c production search
The exact-event development pilot favored simpler coordinate event scans over more elaborate kernel/memory policies on most larger instances. This supports testing the event primitive in production; it does not establish a new research method.

Start from archived boundforge/results/best.json (the actual59/49-point weighted C3c witness), preserving original rational masses. Screen exact rational collision-event locations for point-coordinate, projection-block translation, two-block, and paired-coordinate directions. Optimize the two-law mixture numerically across denominator-envelope breakpoints. Search comparisons are floating screening only, with a1e-9 improvement threshold before expensive final checks.

Eight isolated Modal workers,60 search CPU seconds each,1CPU/1GiB,180s timeout,no retries. Bound coordinate bit length512; this is a search restriction. Use ordinary numerical operator allocation and bounded exploration. Record all inputs/directions, event counts, chosen parameters, screening outcomes, seeds, source hashes and resource allocation. No claim of novel controller or proof-carrying weighted-family exhaustion.

For any retained candidate, recover integer coordinates, preserve positive rational masses, rationalize the mixture, choose a base large enough for digit injectivity, and run both unchanged protected checkers. Compare strictly against the archived best witness. If a candidate clears that hurdle, refresh the public frontier before any record claim. Never call beating an obsolete or rounded value a world record.

This is separate from methodological evaluation and all held-out outcomes. A successful conventional production search does not establish methodological novelty. If no verified improvement emerges, preserve the negative campaign without scaling equivalent trials merely because credits remain.
